# Domain — доменный слой ShoesStoreAPI

Проект содержит доменную модель магазина обуви — сущности, объекты‑значения и базовые контракты, отражающие бизнес‑логику и инварианты.

## Назначение
- Инкапсулировать бизнес‑правила и модели предметной области.
- Быть независимым от инфраструктуры (хранилища, Web, БД).
- Обеспечивать устойчивые инварианты через Value Objects и фабрики.

## Структура
- `Objects/` — сущности (Products, Orders, Users, Categories, Manufacturers, Suppliers, Units, Roles, Statuses, OrderItems).
  - Каждая сущность разделена на два partial‑файла:
    - `*.Initialization.cs` — фабрики: `Create(...)` для создания новых агрегатов и `Restore(...)` для восстановления из БД (internal).
    - `*.Properties.cs` — свойства (VO) и методы для изменения состояния (`Change*`).
- `ValueObjects/` — объекты‑значения:
  - Идентификаторы (`*Id`) — проверка диапазонов.
  - Текстовые и числовые VO (`*Name`, `ProductPrice`, `ProductQuantity` и т.д.) — валидация null/длины/диапазонов.
  - Базовые классы: `ValueObject<TSelf,TValue>` и `NullableValueObject<TSelf,TValue>`.
  - Контракты: `IValueObject` и `INullableValueObject` с фабричным методом `FromValue`.
- `AssemblyInfo.cs` содержит `InternalsVisibleTo("Infrastructure")` для доступа восстановителя.

## Конвенции и паттерны
- Создание агрегата через `Create(...)` — устанавливает новый Id (0) и выполняет валидацию входных VO.
- Восстановление из хранилища через `Restore(...)` — internal, принимает примитивы (id, строки, числа) и создаёт VO без повторной бизнес‑валидации (предполагается корректность БД).
- Изменения состояния выполняются контролируемыми методами `Change*`, принимающими VO.
- Все VO имеют статический фабричный метод `FromValue(...)`, выбрасывающий исключения в случае нарушения инвариантов (используется пакет `Shared.Types.Exceptions.Validation`).
